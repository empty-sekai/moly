# Embedding the MYSEKAI experience

The browser bundle is a standalone same-origin application. Its HTML, CSS and
ES modules have no frontend framework dependency. Rust owns the catalogue,
content eligibility and every playback / cancellation / restoration operation.

Mount `web/` (including both generated `pkg/` backends) at a feature directory,
for example `/moly/`. Mount one complete resource snapshot at an explicit
same-origin directory. The host chooses the snapshot; never merge CN and JP
records by numeric ID. The default asset path is `./assets/` beside the page.

```js
import { mountMoly } from "/moly/embed.mjs";

const experience = mountMoly(container, {
  src: "/moly/",
  assets: "/resources/mysekai/cn/",
  theme: "light",
  // Optional opaque content key from a previous selection:
  content: "talk:general:3912",
  tab: "conversations",
  onSelection: (selection) => {
    /* host may retain this exact content key */
  },
  onStatus: (status) => {
    /* preparing, playing, restoring, idle or error */
  },
});

experience.setTheme("dark");
// On route/component unmount:
experience.dispose();
```

Give the container an explicit height (`height: calc(100dvh - 96px)` is one
option). The embedded document hides its site header. For Moesekai, use the
existing `MainLayout` and its immersive mode when desired. Keep the existing
furniture catalogue and layout preview: this page adds conversation and
interaction playback and does not replace either one. Create the iframe once
per component mount, update its theme without re-mounting, and dispose it on
unmount. Changing the resource snapshot requires a fresh document and app.
The game settings button remains in the stage toolbar in embedded mode;
navigation and the outer theme controls belong to the host.

Standalone hosts may publish `snapshots.json` beside the page:

```json
{
  "version": 1,
  "snapshots": [
    { "region": "cn", "version": "current", "assetBase": "/assets/" },
    { "region": "jp", "version": "current", "assetBase": "/assets-jp/" }
  ]
}
```

When at least two complete snapshots are available, a region picker appears in
the standalone header. Switching replaces the document and clears snapshot-bound
content IDs, search and player preview parameters. The development server
publishes this menu when `MOLY_JP_ASSET_ROOT` is supplied alongside
`MOLY_ASSET_ROOT`. Embedded hosts select the region through `assets` at mount.

`embed.mjs` only accepts a same-origin application URL. Messages require the
expected origin, exact iframe window, schema version and message source. The
host can stop or close the experience and read selection/status notifications;
it cannot inject arbitrary gameplay commands. No message is accepted from an
unrelated window. Removing the iframe destroys its renderer/audio context and
releases the document storage lock; the preview scene never becomes a saved
layout.

Selection links preserve `tab`, `content`, `q`, `character`, `availability`,
`experience`, `page` and the related `fixture` filter. Asset and renderer
parameters remain intact. Opening a link selects content but never auto-plays
sound. A click is required to start the browser app and activate audio.

Character portraits are optional presentation assets generated by the resource
pipeline at `ui/character-portraits/character-portraits.json`. Furniture images
come from the runtime's existing thumbnail manifest. Images load only for the
visible page. Missing images retain readable names; unavailable content shows
a reason and disables playback.

Serve `.wasm` as `application/wasm`, `.mjs` as `text/javascript`, `.css` as
`text/css`, and configure the same-origin asset and player-data API routes.
For packed asset delivery, also expose the presentation image files at their
manifest paths. Asset bundles and player data are deployment inputs and are
not included in this code repository.
